# Shibboleth Integration with Spring Boot Guide

## Introduction

### General Information about the Components

This guide describes the integration between a **Shibboleth Identity Provider (IdP)** running in Docker and a **Spring Boot Service Provider (SP)** using Spring Security SAML2.

---

# Prerequisites

- Eclipse STS on the Service Provider side
- Docker installed with:
  - Ubuntu image
  - Tomcat
  - Shibboleth IdP
- Java 17+
- Maven for Spring Boot
- HTPasswd credential store enabled on the IdP for authentication testing

---

# Docker Port Mapping

To allow communication between the host OS, the IdP, and the Spring Boot application:

| Port Mapping | Purpose |
|--------------|---------|
| `8443:8443` | HTTPS - IdP TLS Endpoint. Used for SAML2 requests, SSO user authentication, and metadata retrieval. |
| `8080:8080` | HTTP endpoint for testing or internal proxying. Typically redirected to HTTPS in production. |
| `8081` | Host Spring Boot Service Provider running at `http://localhost:8081`. |

---

# Core Shibboleth Configuration Files

Location:

```text
/opt/shibboleth-idp/conf
```

| File Name | Function & Purpose |
|------------|-------------------|
| `relying-party.xml` | Defines Service Provider communication policies, SAML2 profiles, signatures, and encryption settings. |
| `attribute-resolver.xml` | Resolves authenticated user attributes and maps them into SAML attributes. |
| `attribute-filter.xml` | Controls which attributes are released to which Service Providers. |
| `saml-nameid.xml` | Defines NameID formats generated by the IdP. |
| `metadata-providers.xml` | Registers external SP metadata files. |

---

# Spring Boot Service Provider Java Components

### SecurityFilterChain / HttpSecurity

Configures:

- Authentication entry point
- `saml2Login()`
- SAML response processing

### RelyingPartyRegistrationRepository

Stores:

- IdP metadata
- SP metadata
- Certificates
- Endpoints

### OpenSaml4AuthenticationProvider / OpenSaml5AuthenticationProvider

Processes incoming SAML assertions received through:

```text
/login/saml2/sso/{registrationId}
```

### GrantedAuthoritiesMapper / Custom SAML User Service

Maps:

- `uid`
- `principal`

into Spring Security authorities.
